# 任务规划与拆解

生成 `TaskGraph`，检查任务层级、依赖、责任、期限和完成标准。

当输入会议纪要时：

1. 定位待办章节，生成所有尚未完成的任务；已明确完成或已解决的事项不得重复派发。
2. 必须先做“任务/会议”分类，再做任务改写和拆解。分类时以纪要原文及证据引文为准，不能以改写后的标题、推断出的交付物覆盖原文语义。
   - 会议本体：凡是召开、参加、组织、出席会议，或“某日/上午/下午携某材料与某方专题对碰、沟通、评审、确认”的安排，无论是否重复、是否写在“会后待办”章节、是否附带预期结论或问题清单，一律生成项目日历事项，不进入任务图。
   - 独立任务：只有纪要明确要求在会前准备、编制、整理、提交某项材料，或会后回写、整改、执行某项结论时，才把该交付动作单独建为任务。不得因为会议需要携带已有材料，就臆造“材料包整理”等任务。
   - 同一句同时包含交付动作和会议安排时，拆成“独立任务 + 日历事项”；分别保留各自日期、负责人、证据，不得把两者合并为一个任务。
   - 每日站会、周例会、定期汇报等重复安排同样进入项目日历。
   - 分类结果必须先通过本 skill 的日历排除检查；不得绕过该检查直接调用存储接口批量写入候选任务。
3. 每项叶子任务必须包含可执行的详细描述、具体实施负责人、截止时间、交付物和可核验的验收口径，不能只复述纪要标题。
4. 对每项任务执行“实施人员测试”：一个被指派的人是否无需再次找下属分工，就能直接回答“我要做什么、产出什么、做到什么程度”。不能通过时必须继续拆分。
5. 当管理者负责汇总、审核、过堂或提交，但输入实际来自多个板块、专业、系统或阶段时，必须先按输入来源建立子任务，再保留管理者的汇总/审核任务。审核任务不能替代板块交付任务。
6. 多负责人共享一个交付物时，必须分别写清每个人的动作和输出；无法在任务说明中区分时，拆成多个叶子任务，并通过前置依赖汇入父级交付。
7. “完成方案”“推进联调”“整体梳理”“盘点初筛”等复合事项，按可独立验收的字段、接口、板块、工序、规则、验证或文档章节继续下钻。不要为了减少任务数量而把执行工作隐藏在管理任务中。
8. 父级任务只承担明确的组装、审核、决策或最终提交交付物；纯进度检查改为里程碑或日历事项，不作为执行待办。
9. 任务说明必须写成给执行人员看的自然工作指令：说明要做什么、做到什么范围、需要注意哪些边界。使用两到三句连贯短句，不得用“任务目标/执行要求/截止要求/提交物/验收方式/原始责任项”把字段机械拼成一段。
10. 负责人、截止时间、交付物和验收口径已有独立字段时，不要在任务说明中再次罗列；只在动作语义需要时自然提及交付成果。
11. “某某团队”“各模块负责人”“相关业务模块”等集合责任不能直接作为最终负责人。应结合当前项目人员结构完整展开为具体负责人；“各模块负责人/相关业务模块/实施团队”必须覆盖人员结构中全部板块或专题负责人，不能用固定的少数默认模块代替。
12. 优先把叶子任务分配给实际编制、配置、开发、测试或验证人员；板块负责人和PMO默认承担确认、统筹或验收，除非任务本身就是其亲自完成的明确交付物。
13. 人员结构不能唯一支持映射时，不得臆造姓名。应生成带明确交付物的“分工确认表”候选，由项目经理或板块负责人确认；不得用含糊的“相关人员”代替实施负责人。
14. 外部组织可以作为协同方保留，但不能替代交付方的具体主责人。
15. 对照来源逐项核数：`来源事项数 = 已生成叶子任务覆盖数 + 有证据的已完成/已解决排除数 + 已生成日历事项数`。日历事项必须带日期、时段（原文只有“下午”就保留为“下午”，不得编造具体时刻）、标题、参与/主责人和证据。任何漏项、重复项、未下钻管理项或无来源新增项都必须告警，不得静默发布。
16. 候选任务经确认发布后，初始状态统一为 `open`，页面文案为“待开始”。正式任务状态只使用 `open/in_progress/pending_acceptance/done/canceled`，不得生成或跟踪 `blocked` 状态；阻碍、依赖和风险应进入风险或依赖字段。
17. 状态不做顺序流转限制。当前负责人可以在“待开始、进行中、待验收、已完成、已取消”之间直接修改；非当前负责人不得修改任务状态。状态操作必须在任务清单中完成，并同步到个人看板、团队任务清单和进度总览。
18. 转派编辑必须带入当前负责人列表，允许增删改；保存后按新的完整负责人列表流转到对应个人看板。不得要求用户重新录入整份负责人清单。
19. 每个候选任务生成时必须同时写入项目进度总览所需的 `board_id` 和 `professional_id`。板块优先依据纪要原文中的明确板块，其次依据任务标题和唯一负责人组织归属；专业依据实际工作性质归入产品/需求设计、软件开发、数据与接口、测试/UAT或实施上线。无法唯一归类时保留待归类并告警，不得臆造；候选任务在发布前即进入总览，发布后沿用原分类且不得重复计数。
20. 生成后必须验收：会议本体（包括一次性专题对碰）没有混入任务；所有识别出的会议均已形成项目日历事项；会议已有材料没有被臆造为新的准备任务；所有父级汇总/审核任务都有完整子任务输入；每个叶子任务能通过“实施人员测试”；负责人映射完整；来源覆盖平衡；板块与专业分类完整；状态与进度总览映射一致。临时测试批次必须可按来源标记并支持后续精确清理。

正式分工、资源承诺和基线计划必须由负责人确认；本 skill 只输出候选任务，不直接发布正式任务。
